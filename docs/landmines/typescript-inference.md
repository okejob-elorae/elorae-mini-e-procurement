# TypeScript inference landmines

The full entries behind the **TypeScript inference** triggers in `AGENTS.md` § Landmine index, in the same order. Each one was written after someone paid for it. Read the entry for whatever surface you are about to touch before writing code; where an entry points on to `docs/ARCHITECTURE-NOTES.md`, `docs/EPIC-STATUS.md` or `docs/FOLLOWUPS.md`, follow it. When a change makes an entry wrong, fix it here in the same session — and update its trigger in `AGENTS.md` if the trigger itself moved.

- Writing TS a subagent cannot compile? Five inference shapes have shipped as build breaks — truthiness that never narrows a `string` union member, a spread whose index signature erased the concrete fields, a library constructor missing a required param, a property narrowing lost inside a nested closure, and a next-intl key cast `as never`, which also kills its values parameter. They surface only in `type-check` — vitest does not type-check. That is the owner's to run locally, never a subagent's, and CI's `checks` job also runs it on every PR to `master`. CI is not a required check and does not gate the deploy, so an error merged past a red run still fails the web image build, which blocks the gated `migrate` job. Detail + the fix for each in `AGENTS.md` § Code conventions.
