# Print documents landmines

The full entries behind the **Print documents** triggers in `AGENTS.md` § Landmine index, in the same order. Each one was written after someone paid for it. Read the entry for whatever surface you are about to touch before writing code; where an entry points on to `docs/ARCHITECTURE-NOTES.md`, `docs/EPIC-STATUS.md` or `docs/FOLLOWUPS.md`, follow it. When a change makes an entry wrong, fix it here in the same session — and update its trigger in `AGENTS.md` if the trigger itself moved.

- Injecting a `lib/print/*-html.ts` builder's output with `dangerouslySetInnerHTML`? Only TWO of them may be injected — `spg-sale-nota-html.ts` and `van-sale-nota-html.ts` return class-scoped `<div>` fragments; EVERY other builder returns a full `<!DOCTYPE html>` document, and its embedded `printCssBase` is unlayered, so fragment parsing drops the `<html>`/`<body>` wrapper, attaches the `<style>` anyway, and the whole app takes the print sheet's padding, white background, font size and `--border` for as long as the route stays mounted. Both families return a bare `string` and nothing distinguishes them at compile time — only the NAME does: a document is `build<Thing>Html(opts)` (fourteen, all taking one options object), a fragment is `<thing>NotaHtml(sale)` (`spgSaleNotaHtml`, `vanSaleNotaHtml`, both taking the domain entity). Full-document builders go in an iframe: a visible `<iframe srcDoc>` for a preview screen, `printHtmlInIframe` for print-only. Shipped as a live defect on the BKM view, caught in review. See `docs/ARCHITECTURE-NOTES.md`.
- Building a new printable document and reaching for `PrintLayout` + `print.css`? Wrong family — `app/print/**` + `components/print/PrintLayout.tsx` is the analytical REPORT pattern (balance sheet, cash flow, income statement, trial balance, WO reconciliation). A transaction document is a pure `lib/print/<doc>-html.ts` builder over `print-theme.ts` with a locale-agnostic `labels` object. The settlement BKM's own epic card asked for the wrong one — so the scope text you are handed is not authority here. See `docs/ARCHITECTURE-NOTES.md` and `docs/EPIC-STATUS.md`.
- Auto-sizing an iframe to its own content? Measure `contentDocument.body`, NEVER `documentElement` — the root element's box fills the initial containing block, so its `scrollHeight` is floored at the viewport height and the frame can only ever grow: a short document keeps its placeholder dead space forever and a rotation to a wider viewport can never shrink it back. A `ResizeObserver` on top of the wrong element fixes one direction only. Poll `readyState` rather than trusting a one-shot `srcDoc` `load`, and cap the poll. See `docs/ARCHITECTURE-NOTES.md`.
- "Harmonising" the BKM's money formatting onto the whole-rupiah `idr` its neighbours use? Don't — `settlement-bkm-html.ts` renders 2dp on purpose, matching the settlement screens it is the paper artifact of, because every figure behind it carries sen (`Decimal(15,2)` receivables, a documented sub-rupiah `PARTIAL` residue). Rounding makes the invoice column visibly not add up on a page the store signs, and prints a −0,40 variance as −Rp 0 on the copy the store keeps. Whole rupiah is the minority spelling anyway: two builders still hold their own `Math.round` formatter and every other one is 2dp. Change all of a document's money or none. `field-sales-nota-tagihan-html.ts` went 2dp whole (PR #476), so its line columns visibly add up and its whole-rupiah grand total prints `,00`; like the BKM it keeps a file-local `id-ID` formatter rather than `print-theme.ts`'s `money()`, whose host-locale output differs between environments. One deliberate mixed document exists: the van/SPG thermal nota prints whole-rupiah throughout except its Subtotal and "Pembulatan tunai" rows, which are 2dp because they exist only to show the sub-rupiah gap a whole-rupiah TOTAL rounded away (see `docs/ARCHITECTURE-NOTES.md`) — leave that split alone.
- Adding a backoffice print trigger? Call `lib/print/print-html-in-iframe.ts`, do not hand-roll one. It was extracted from two copies that had ALREADY drifted apart silently — one removed the iframe on an unconditional 1s timeout with no error path, the other returned early with a toast — and every hidden-iframe print in `app/backoffice` now goes through it (PR #472); the `window.open` popups (the van/SPG thermal nota, Nota Kain per Roll) are a different shape and stay popups. Audit the print too — every print surface now writes one, and a new trigger must: a `PRINT` row through `logPrintQuietly` (`apps/web/lib/audit/log-print-quietly.ts`), with an entity type naming the document rather than the surface, fired and never awaited. Never `await` the audit — or any network call — ahead of `window.open` in a click handler: the await spends the click's user gesture and the popup blocker kills the window. Log AFTER the popup guard (`if (!win) return;`), so a blocked popup records no print; `printHtmlInIframe` returns nothing and handles its own failure (a toast, in the caller's language when the caller passes `errorMessage`), so a trigger built on it can only log beside it. The older triggers that `await logPrint(...)` before an iframe print are not popup-bound, but a rejected audit still stops their print — do not copy them. A page that prints itself on mount (the marketplace pick list and packing slip, the work-order reconciliation route, the four `app/print/finance/*` statements) logs inside the same effect — behind a `useRef` flag, or inside the delayed print timer whose cleanup cancels it — so React StrictMode's double effect logs once. The finance statements key the audit on the report's period label, having no row id.
- Adding or rewording a finance statement note (Neraca, Laba Rugi, Arus Kas, Trial Balance) for print or Excel? The text lives ONCE, in `apps/web/lib/i18n/messages/id.json`; `apps/web/lib/finance/reports/disclosures.ts` reads it by key (a small `fill()` for `{date}`/`{count}`) and is SERVER-ONLY — it imports the whole `id.json`. The `app/print/finance/*` pages are `"use client"`, so they never import it by value: the `get*Report` actions in `app/actions/finance-reports.ts` return a `notes` object built by its `*PrintNotes` helpers, and the pages read `report.notes.*`. Never restate a note as a literal in `disclosures.ts` (a `disclosures.test.ts` coverage case pins every exported string to its key), and never import `disclosures.ts` from a client file. A note that only makes sense in some states (the cash flow single-period note needs a comparison) is gated in the `*PrintNotes` helper, not the page (PR #475).
